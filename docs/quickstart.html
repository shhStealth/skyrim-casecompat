CaseCompat Quickstart

Fix filesystem case-mismatches in a modded Skyrim Special Edition install on Linux.

A mod can ship the exact file Skyrim needs and still spell its path differently from what a plugin requests — meshes vs Meshes. Windows never notices; a case-sensitive Linux filesystem does, and that's what breaks a heavily modded install. CaseCompat finds every file your load order actually asks for, checks it against what's really on disk, and corrects the case wherever they disagree — nothing else in your install is touched.

Before you start

This is early tester software. It renames real files in your Data folder. The tool is designed to be safe — every rename is journaled and reversible (Step 5) — but until it's had more real-world mileage, back up anything you'd hate to lose, or at least know how to verify/reinstall your game files if something looks wrong.

It's also safe to close it partway through with Ctrl+C — nothing is left half-done, and re-running picks up where it left off.

  1. Install prerequisites

    CaseCompat targets net10.0 and needs the .NET 10 SDK to build and run from source. You'll also need git to get the code.

    # Debian / Ubuntu / Mint
sudo apt install git dotnet-sdk-10.0

    On Fedora, use dnf install git dotnet-sdk-10.0; on Arch, pacman -S git dotnet-sdk. Other distros: see Microsoft's install guide.

    Confirm it installed:

    dotnet --version

  2. Get the source

    Clone the repository and move into it:

    git clone https://github.com/shhStealth/skyrim-casecompat.git
cd skyrim-casecompat

  3. Build

    From the repository root:

    dotnet build

  4. Run it

    Launch with no arguments and confirm each prompt — it auto-detects your Skyrim Data folder, Plugins.txt, and loadorder.txt, then walks you through the scan and repair:

    dotnet run --project src/CaseCompat.Cli --
# review what it finds, then press y to confirm
    large collection → can take a while

    For a big mod list, the scan and apply can run for a long time — it's opening and checking a huge number of real files, not stuck. It shows live progress the whole way, and will automatically rescan and reapply as many times as it takes to settle on its own (no need to re-run it yourself).

    When it's done, it prints where it saved a full CSV report and the journal it just wrote — typically under ~/.local/share/CaseCompat/installs/<install-id>/. You'll want that journal path for Step 5 if you ever need to undo the run.

  5. Roll back a previous run

    Changed your mind, or something looks wrong after a run? Rollback is guided the same way — no journal paths or plan IDs to dig up by hand. 

    dotnet run --project src/CaseCompat.Cli -- rollback
# re-detects the same install, finds its journal,
# shows how many applied fixes it found, then confirm to undo

    It re-verifies each file's exact identity before renaming it back, and refuses to touch anything that's changed since — it won't guess.

Full command reference

Diagnostics, scripted batch mode, and rolling back one specific fix by plan ID instead of the whole run: 

dotnet run --project src/CaseCompat.Cli -- --help
targeted-consumer-candidates targeted-consumer-batch-apply targeted-consumer-rollback doctor

Good to know

  • A fix is a rename, not a copy — there's never a second file on disk for the same asset.
  • Every rename is planned, journaled, and freshly re-verified before it touches anything, and refuses to apply or roll back whatever it can't prove it owns.
  • A case fight it can't safely resolve on its own — two real folders that already exist under both casings your mods disagree about — is reported and left alone, not guessed at.
  • One folder, two casings your mods need at once? It links a second name to the same real folder rather than renaming anything, so both mods keep working.

Found a problem?

Early tester feedback is exactly what this phase is for — please report anything that looks wrong, including the exact command you ran and what the tool printed, on the GitHub issue tracker.
