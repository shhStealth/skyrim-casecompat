Modded Skyrim SE on Linux

A practical path from Steam to a playable large modded install — for any big Vortex-managed collection, not one specific list.

Large Nexus Collections generally aren't built or tested against Linux. This guide started as notes for one specific collection and has been generalized here based on real testing across several different collections and machines — including a 700GB collection, a 25GB one, and a Steam Deck. The technical explanations are kept short and only appear where they help you avoid a common mistake.

About this guide

This is a general community resource for running large modded Skyrim collections on Linux — Steam/Proton setup, Vortex configuration, memory, and crash triage. It's maintained alongside CaseCompat but isn't part of the tool itself: CaseCompat solves one specific problem (path-casing mismatches); this guide covers everything around it.

Before you start

Back up your Skyrim Data folder and Vortex staging folder (not just your saves — saves aren't what these steps touch) before changing filesystem attributes, Wine registry values, swap, deployment paths, or loose assets.

Important path note

Commands here use example paths. Your Steam library may be somewhere else. Replace the example Steam library path with your real one before running a script. Don't type a literal ~ inside quotation marks and expect it to expand — use $HOME or a full path instead.

Quick start — the whole process

If you only want the roadmap, these are the steps. The rest of the page explains each one.

  1. Install Steam and Skyrim — launch once and let Anniversary Edition/Creation Club content finish installing.
  2. Install ProtonUp-Qt and SteamTinkerLaunch — add GE-Proton, select STL as Skyrim's compatibility tool.
  3. Install Vortex inside Skyrim's own Proton prefix — not STL's separate managed prefix.
  4. Put Vortex staging beside Skyrim — same Linux filesystem, for hardlink deployment.
  5. Install your collection — check its Nexus page for the real disk-space figure; treat that as a minimum.
  6. Create a real, empty Data/data folder — prevents an extremely slow Wine path-lookup fallback.
  7. Run BethINI Pie; consider VRAMr — get the base collection working before mass texture optimization.
  8. Check RAM and swap — large modlists can exhaust memory without a normal Skyrim crash log.
  9. Launch through a simple, guarded script — raises the file-descriptor limit and keeps Data/data safe.
  10. Classify problems before reacting — a crash log, a freeze, and a silent Linux kill are different problems with different fixes.

Disk space planning

Collection sizes vary enormously. On one tested ~700GB collection, downloads were roughly 250GB and the unpacked staging footprint approached 600–700GB, with VRAM-optimizer output adding more; a ~25GB collection needs a small fraction of that. Check your specific collection's stated size and treat it as a floor, not a comfortable ceiling — then add headroom.

1 · Install Steam and Skyrim Required

Install Steam using your distro's normal package method. On Mint/Ubuntu-family systems, avoid mixing several Steam packaging methods in the same setup — prefer the normal Debian/Ubuntu-style install over a Snap-based one.

# Debian / Ubuntu / Mint
sudo apt update
sudo apt install steam-installer

If steam-installer isn't your distro's package name, use that distro's own documented Steam package instead.

Install Skyrim Special Edition

  1. Install The Elder Scrolls V: Skyrim Special Edition from Steam.
  2. Launch it once from Steam before modding it.
  3. Let the Anniversary Edition / Creation Club content finish installing.
  4. Quit Skyrim only after that first-run download has settled.

The first launch creates Skyrim's own configuration data and lets Steam finish game-owned content. Doing this before Vortex avoids mixing first-run game changes with collection deployment.

2 · Install GE-Proton Required

Install ProtonUp-Qt using the method appropriate for your distro, then use it to add GE-Proton — the build every script in this guide talks to directly by path.

  1. Open ProtonUp-Qt.
  2. Add the latest GE-Proton as a compatibility tool for Steam.
  3. Restart Steam if it doesn't appear immediately.

You don't need to set this in Steam's UI

Every launcher in this guide — Vortex (Step 3A) and Skyrim itself (Step 9) — calls GE-Proton directly by path and never goes through Steam's own launch mechanism. You don't need to open Skyrim's Properties → Compatibility and force a specific Play tool at all, unless you also want a working Steam “Play” button as a convenience or fallback (for Steam Overlay/Input) — if so, just point that setting at the same GE-Proton build your scripts already use.

Optional: SteamTinkerLaunch, for one-off Windows tool launches

STL isn't required for Vortex or Skyrim in this guide — both launch through their own small scripts instead. It's still convenient later for running an occasional Windows-only utility (BethINI Pie in Step 7) inside the right Proton environment without writing a new script for each tool.

STL doesn't bundle everything it needs to run. Install its dependencies first — most notably yad, the dialog toolkit its whole UI is built on:

# Debian / Ubuntu / Mint
sudo apt install yad

On Fedora, dnf install yad; on Arch, pacman -S yad. Package names vary, and STL depends on a few other common CLI tools beyond just yad — its own wiki keeps the complete, version-current list, and STL can check for and report missing dependencies the first time you run it.

  1. Add SteamTinkerLaunch as a Steam compatibility tool via ProtonUp-Qt, the same way as GE-Proton above.
  2. If you want to use it for one-off tool launches, assign it as Skyrim's compatibility tool (Properties → Compatibility, as above) and run it once from Steam's Play button so it can finish its own first-time setup. This doesn't change how you'll actually launch the game later — Step 9 uses its own script either way.

3 · Install Vortex directly in Skyrim's Proton prefix Required

The Vortex installation this guide uses must live inside Skyrim Special Edition's own Proton prefix (Steam AppID 489830). This is the step that's easiest to get wrong on Linux.

Don't assume STL uses the Skyrim prefix

SteamTinkerLaunch normally keeps its own managed Vortex under ~/.config/steamtinkerlaunch/vortex/compatdata/pfx — a separate prefix. If you use steamtinkerlaunch vortex install, verify where Vortex actually landed before starting your collection.

1. Identify Skyrim's prefix and an x86-64 GE-Proton build

STEAMLIB="/mnt/Speedy/SteamLibrary"    # change this
COMPAT="$STEAMLIB/steamapps/compatdata/489830"
GE_PROTON="$HOME/.steam/debian-installation/compatibilitytools.d/GE-Proton11-5-x86_64"

uname -m
file "$GE_PROTON/files/bin/wine"

On a normal Intel/AMD PC, uname -m reports x86_64. Never select an aarch64/ARM Proton build on an x86_64 machine. Your GE-Proton folder name will include whatever version you installed.

2. Run the Vortex installer inside Skyrim's prefix

export WINEPREFIX="$COMPAT/pfx"

"$GE_PROTON/files/bin/wine" \
  "/path/to/vortex-setup-<version>.exe"

Use the real installer path

Point the command at the installer you actually downloaded. If STL already downloaded one, check ~/.config/steamtinkerlaunch/downloads/vortex/.

3. If Vortex asks for .NET

Install the Windows .NET Desktop Runtime it requests into this same prefix — not the Linux .NET package. Newer Vortex builds may include the Windows runtime installer under resources/temp after installation.

"$GE_PROTON/files/bin/wine" \
  "$COMPAT/pfx/drive_c/Program Files/Vortex/resources/temp/windowsdesktop-runtime-win-x64.exe"

4. Verify the final location

ls -lh "$COMPAT/pfx/drive_c/Program Files/Vortex/Vortex.exe"

3A · Launch Vortex and handle Nexus links

Once Vortex is installed in Skyrim's prefix, launch it directly with a small script rather than through Steam or STL — it talks to GE-Proton by path the same way Step 9's game launcher does. The script below also handles Nexus nxm:// links by adding the required --download argument.

If Vortex was first installed to STL's separate prefix

Don't copy the whole Wine registry into Skyrim's prefix. Rerun the Vortex installer with WINEPREFIX set to Skyrim's 489830 prefix instead — copying program files alone can leave a stale uninstall key until it's reinstalled correctly.

Create ~/bin/vortex

mkdir -p ~/bin
nano ~/bin/vortex

#!/bin/bash
STEAMLIB="/mnt/Speedy/SteamLibrary"    # change this
COMPAT="$STEAMLIB/steamapps/compatdata/489830"
GE_PROTON="$HOME/.steam/debian-installation/compatibilitytools.d/GE-Proton11-5-x86_64"
WINE="$GE_PROTON/files/bin/wine"
VORTEX="$COMPAT/pfx/drive_c/Program Files/Vortex/Vortex.exe"
export WINEPREFIX="$COMPAT/pfx"

if [[ "$1" == nxm://* ]]; then
    "$WINE" "$VORTEX" --download "$1" &
else
    "$WINE" "$VORTEX" "$@" &
fi

Save the file, then make it executable. Mint commonly adds ~/bin to PATH after a new login if the folder exists.

chmod +x ~/bin/vortex
~/bin/vortex
command -v vortex

Register Nexus nxm:// links with Linux

mkdir -p ~/.local/share/applications
cat > ~/.local/share/applications/vortex-nxm.desktop <<EOF
[Desktop Entry]
Name=Vortex NXM Handler
Exec=$HOME/bin/vortex %u
Type=Application
NoDisplay=true
MimeType=x-scheme-handler/nxm;
EOF

update-desktop-database "$HOME/.local/share/applications"
xdg-mime default vortex-nxm.desktop x-scheme-handler/nxm
xdg-mime query default x-scheme-handler/nxm

The unquoted EOF above expands $HOME while the file is being created, so Exec receives an absolute path. The final command should print vortex-nxm.desktop. When you click “Download with Manager” on Nexus, choose Vortex NXM Handler.

LibreWolf / hardened Firefox only, if the NXM chooser doesn't appear

Open about:config. Set network.protocol-handler.expose.nxm = false and network.protocol-handler.external.nxm = true. Restart the browser, then click an actual Nexus “Download with Manager” link again.

4 · Configure Vortex storage correctly Required

Once Vortex detects Skyrim, set the game and staging paths before you start your collection.

Game + staging: same filesystem

Skyrim and the Vortex mod staging folder must be on the same Linux filesystem for hardlink deployment. Being on the same physical disk isn't enough if that disk is split into different mounted filesystems.

df -T "/path/to/Skyrim Special Edition"
df -T "/path/to/Vortex Mod Staging"

The filesystem/device information should match. The mod download folder is different: it can live on another drive because Vortex doesn't deploy from the download archive folder.

FolderWhere it can livePractical advice
Skyrim game folderLinux-native filesystem (ext4 tested)Prefer SSD.
Vortex mod stagingSame filesystem as SkyrimThis is the important hardlink requirement.
Vortex downloadsAny drive with enough spaceHDD is usable; SSD is faster.

5 · Start your collection Required

  1. In Vortex, open Skyrim Special Edition.
  2. Open Collections and locate the one you want — or start it from that collection's own Nexus Mods page.
  3. Begin the download/install process and let Vortex work through it.
  4. Don't move Skyrim or the staging folder after deployment has started unless you understand the consequences for hardlinks.

Optional Vortex speed workaround (experimental)

On tested setups, switching Vortex to a harmless dummy managed game (a Stardew Valley install, for instance) while a large collection's download/install process runs made that process noticeably faster. Treat this as optional and experimental, not a requirement — switch back to Skyrim before deploying or launching.

6 · Create the Data/data startup fix Required

This is one of the most important Linux-specific fixes in this guide. On a large plugin setup (4,000+ plugins tested), a missing inner Data/data directory can make Wine perform extremely expensive case-insensitive path searches against the whole Skyrim Data tree.

Observed result

Creating a real, empty Data/data directory reduced pre-main-menu startup from roughly 30–70 minutes to about 1–2 minutes on the tested installation.

GAME="/mnt/Speedy/SteamLibrary/steamapps/common/Skyrim Special Edition"
mkdir -p "$GAME/Data/data"
ls -ld "$GAME/Data/data"
find "$GAME/Data/data" -mindepth 1 -print

The final find command should print nothing.

Data/data must be…Why
A real directoryThe workaround depends on it existing as a normal filesystem object.
Completely emptyIt's only there to make a fallback lookup fail quickly.
Not a symlinkDon't point Data/data back at Data, ., or any other directory.

Don't “fix” this by changing case everywhere

Linux filename case can matter in modded Skyrim, but not every mismatch is a bug. Don't lowercase the entire Data tree, recursively add ext4 casefold attributes, or duplicate every differently-cased asset. Use narrow fixes only when a specific asset path is proven broken — or use a dedicated tool built for exactly this (see “Case-sensitive files” below).

7 · Run BethINI Pie; decide whether to use VRAMr Optional

BethINI Pie

Run BethINI Pie through SteamTinkerLaunch using its one-time launch feature. This keeps the tool inside the same Windows/Proton environment as Skyrim.

Reducing VRAM usage: prefer Texture Downscaler over VRAMr

If your GPU's VRAM is tight relative to your collection's texture load — common on 8–12GB cards paired with texture-heavy collections — the Texture Downscaler mod has proven more reliable in practice than VRAMr and is the current recommendation.

  1. First launch the collection without any texture-optimizer output and establish a baseline.
  2. If you need lower VRAM usage, install and run Texture Downscaler using its own documented process, starting from a moderate preset rather than the most aggressive one.
  3. If a model later shows a large missing-model “!” or invisible equipment, don't automatically blame the optimizer or a bad texture. Check the mesh path and filename capitalization first — or just check what CaseCompat's scan already reported for that asset.
  4. If troubleshooting becomes unclear, temporarily remove the optimizer's output and A/B test one variable at a time.

Why the texture warning matters

A confirmed armor-failure case looked like bad optimization but was actually a Linux case-path split: the plugin requested one capitalization while the generated mesh existed under a different, differently-cased real directory. Restoring the original textures didn't fix it; making the mesh reachable at the exact requested path did — see “Case-sensitive files” below for the tool that now automates finding and fixing exactly this.

8 · Check RAM and swap Required

A large modlist can exhaust RAM and swap without producing a normal Skyrim crash log. On one tested 32GB RAM system, an initial 2GB swapfile wasn't enough — the Linux kernel killed Skyrim under memory pressure. Increasing swap to 32GB provided useful overflow capacity. That figure is a tested example, not a universal requirement.

Check before changing anything

free -h
swapon --show

Look at the Swap line before changing anything. If Skyrim suddenly disappears with no CrashLogger log during a heavy scene or long session, check the Linux kernel log for an out-of-memory kill before assuming a mod caused the failure.

Swap is not a speed feature

Swap gives Linux room to survive temporary memory pressure; it doesn't make Skyrim faster. Use a method appropriate to your distribution and existing disk layout rather than blindly replacing a working configuration. Verify the result afterward with free -h and swapon --show.

9 · Create a simple Skyrim / SKSE launcher Required

This launcher keeps the safeguards that are broadly useful for a basic user: it raises the per-process file-descriptor limit, checks Steam is already running, recreates the real empty Data/data directory, and launches SKSE through Skyrim's own Proton environment.

No SteamTinkerLaunch required here

This script calls GE-Proton directly by path, the same way the Vortex launcher in Step 3A does. It doesn't depend on SteamTinkerLaunch or on Steam's own compatibility-tool setting at all — you can run this from a terminal with Steam merely running in the background.

Suggested ~/bin/skyrim-launch

#!/bin/bash

# Change these to your real paths.
STEAMLIB="/mnt/Speedy/SteamLibrary"
GAME="$STEAMLIB/steamapps/common/Skyrim Special Edition"
COMPAT="$STEAMLIB/steamapps/compatdata/489830"
PROTON="$HOME/.steam/steam/compatibilitytools.d/GE-Proton11-5-x86_64"
STEAM="$HOME/.steam/debian-installation"

# Large modlists can exceed the default Linux soft file limit.
ulimit -S -n 16384 || {
    echo "ERROR: Could not raise NOFILE limit."
    exit 1
}

if ! pgrep -x steam >/dev/null 2>&1; then
    echo "ERROR: Steam is not running."
    echo "Start Steam normally, then run this launcher again."
    exit 1
fi

# Keep Data/data as a real, empty directory.
INNER_DATA="$GAME/Data/data"
if [ -L "$INNER_DATA" ]; then
    echo "ERROR: $INNER_DATA must be a real directory, not a symlink."
    exit 1
fi
if [ -e "$INNER_DATA" ] && [ ! -d "$INNER_DATA" ]; then
    echo "ERROR: $INNER_DATA exists but is not a directory."
    exit 1
fi
mkdir -p "$INNER_DATA" || exit 1
if find "$INNER_DATA" -mindepth 1 -print -quit | grep -q .; then
    echo "ERROR: $INNER_DATA is not empty."
    echo "Refusing to launch until it is inspected."
    exit 1
fi

if [ ! -x "$PROTON/proton" ]; then
    echo "ERROR: Proton build not found: $PROTON/proton"
    exit 1
fi
if [ ! -f "$GAME/skse64_loader.exe" ]; then
    echo "ERROR: SKSE loader not found: $GAME/skse64_loader.exe"
    exit 1
fi

cd "$GAME" || exit 1
STEAM_COMPAT_CLIENT_INSTALL_PATH="$STEAM" \
STEAM_COMPAT_DATA_PATH="$COMPAT" \
STEAM_COMPAT_INSTALL_PATH="$GAME" \
SteamAppId=489830 \
SteamGameId=489830 \
"$PROTON/proton" run "$GAME/skse64_loader.exe"

Finish the launcher setup

mkdir -p ~/bin
nano ~/bin/skyrim-launch
# paste the script above, save and exit

chmod +x ~/bin/skyrim-launch
~/bin/skyrim-launch

For most users, the only lines that need to change are the paths at the top. If your Steam client or Proton build live somewhere nonstandard, update those variables too.

10 · If something goes wrong, classify it first Required

Don't start disabling random mods until you know what kind of failure you actually had.

A crash-*.log appearsCrashLogger log in Documents/My Games/Skyrim Special Edition/SKSENormal Skyrim crash — analyze the log first.
Game freezes but process stays aliveProcess state, CPU/GPU activity, kernel messagesA hard freeze — different from a normal crash.
Game disappears with no crash logLinux kernel log for OOM or NVIDIA eventsCould be an OS memory kill or GPU/driver event.

sudo journalctl -k --since "10 minutes ago" --no-pager | \
grep -Ei 'oom|out of memory|killed process|NVRM|Xid|GPU|Skyrim|wine'

Case-sensitive files

Windows generally treats path capitalization as equivalent. Most Linux filesystems normally don't. A large mod collection assembled from thousands of files across different tools and archives can end up with two real folders whose names differ only by capitalization — and a plugin that requests one exact spelling has no way to find content that only exists under the other.

Example proven in-game

One plugin requested meshes/example folder/Some Armor/… while a generated mesh existed under meshes/example folder/some armor/… — two different real directories below Data/meshes, differing only by case. Copying the exact same mesh bytes to the capitalization the plugin actually requested fixed it; nothing about the texture itself was wrong.

CaseCompat: this is now automated

Diagnosing and fixing this by hand — the manual process the rest of this section describes — is exactly what CaseCompat now does automatically. It scans your actual load order, finds every mismatch between what a plugin requests and what physically exists on disk, and corrects it with a reversible rename — or, when two mods genuinely disagree about a shared folder's casing and both have real content there, links a second name to the same folder rather than guessing which mod is “right.” Every fix is planned, journaled, and can be rolled back with a single guided command. See its quickstart guide for setup and rollback instructions.

The manual reasoning below is still worth understanding — it's exactly what CaseCompat automates, and it explains what its output means if you're curious or hit a case it can't safely resolve on its own.

When should a basic user act manually?

  • Act when a specific mod is broken and you can identify the exact loose asset path it expects.
  • Act when two real folders/files differ only by case and the required assets are split between them.
  • Don't act just because a scanner reports capitalization differences — many are harmless.
  • Remember a file may be inside a BSA archive, so a missing loose file alone doesn't prove the asset is missing.

Never use broad destructive fixes

Don't lowercase the whole Data tree. Don't recursively add ext4 casefold attributes to an existing populated mod tree. Don't blindly duplicate every case mismatch. Narrow, reversible fixes are safer — which is exactly the constraint CaseCompat itself is built around: it reports and skips anything it can't resolve without guessing, rather than forcing a fix.

What to include when asking for help

  • What you were doing immediately before the failure.
  • Whether a new crash-*.log was created.
  • For a freeze, whether SkyrimSE.exe is still running.
  • For a no-log disappearance, the relevant kernel log lines.
  • For a missing model/texture, the exact in-game item and the suspected asset path if known — or just what CaseCompat's read-only scan reported for it.
  • Whether the problem still occurs after removing a recent optimizer or generated-output change.

Final takeaway

Get the Linux/Proton foundation right first: a normal Steam install, Skyrim initialized once, Vortex in the correct prefix, game and staging on the same filesystem, the real empty Data/data fix, enough RAM/swap headroom for the modlist, and a simple guarded SKSE launcher. After that, troubleshoot one failure class at a time. On Linux, a correct mod can still fail because its path isn't exposed the way the Windows-built game expects — run CaseCompat as part of your normal setup, and prefer narrow, reversible fixes over broad filesystem changes for anything it doesn't already catch.
